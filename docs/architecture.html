Architecture

Version: v1.0.0

Last updated: 2026-06-26

This document describes the system architecture of Remote Mouse — how components fit together, data flow, and design decisions for the current version.

System Overview

Remote Mouse follows a simple client-server architecture. The Python server runs on the laptop and serves a web page. The phone connects over WebSocket and sends touch events. The server translates those into OS-level mouse and keyboard actions via pyautogui.

There is no database and no persistent storage beyond events.log and .tunnel_url. The design prioritizes zero phone installation and minimal latency while incorporating layered security: pairing authentication, rate limiting, action allowlisting, CORS validation, PII redaction, and security headers.

All event handlers are gated by @with_ratelimit (30 calls/s per action) and most require a paired session via require_auth(). Unknown events are silently dropped by the ALLOWED_ACTIONS allowlist.

5. Cloudflare Tunnel (cloudflared)

External binary creating a secure HTTPS tunnel from Cloudflare's edge to localhost:5000.

graph LR
    PHONE["Phone Browser<br/>Internet"] -- "HTTPS" --> CF["Cloudflare Edge<br/>trycloudflare.com"]
    CF -- "Tunnel" --> CF_BIN["cloudflared<br/>on Laptop"]
    CF_BIN -- "localhost:5000" --> SERVER["Python Server"]

Provides:

  • Public HTTPS URL on any network
  • No port forwarding, no static IP, no DNS config
  • DDoS protection and edge caching

Limitations:

  • URL changes on every restart (free tier)
  • Idle timeout after several hours
  • Adds 50–200 ms latency vs local access

All log output passes through PIIRedactFilter, which redacts email addresses, URLs, and non-loopback IP addresses before writing to file or displaying to console. Logs are stored in .remote_mouse_logs/events.log (directory created with 0o700 permissions).

Security Model

Remote Mouse uses a layered security model with authentication, rate limiting, input validation, and data redaction:

1. Pairing Authentication

  • A 6-char hex code (PAIRING_CODE) is generated at server start via secrets.token_hex(3).upper()
  • Printed to terminal and exposed at GET /api/pairing-code
  • Client submits the code via the pair socket event; server returns paired with a session token or pair_error
  • All mouse/keyboard socket handlers call require_auth() and reject unpaired sessions
  • Token is stored in localStorage as rm_token and sent on reconnect for persistent auth

2. Rate Limiting (RateLimiter)

  • Per-action, per-session token bucket: max_calls=30, window=1.0s
  • The @with_ratelimit decorator wraps all socket handlers
  • Exceeded calls are silently dropped (no emit back to client)

3. Action Allowlist (ALLOWED_ACTIONS)

  • Only known event names are processed; unknown socket events are log_warn-ed and dropped
  • Allows: mouse_move, mouse_abs, click, scroll, media, mouse_down, mouse_up, request_tunnel_url, disconnect

4. Key Blocklist (BLOCKED_KEYS)

  • Dangerous OS combos are blocked before pyautogui execution
  • Blocked: ctrl+alt+del, ctrl+shift+esc, alt+f4, win+l, win+r, win+x, win+d, alt+tab, ctrl+alt+tab
  • Blocked attempts are logged as warnings

5. CORS Validation (allowed_origin)

  • Dynamic function replaces the wildcard "*" on cors_allowed_origins
  • Accepts: http://localhost:5000, http://127.0.0.1:5000, http://{LAN_IP}:5000, and the active tunnel URL
  • All other origins receive HTTP 403

6. Security Headers

Applied on every response via @app.after_request:

X-Frame-Options: DENY
X-Content-Type-Options: nosniff
X-XSS-Protection: 0
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; frame-ancestors 'none'
Referrer-Policy: no-referrer
Permissions-Policy: geolocation=(), microphone=(), camera=()

7. PII Redaction (PIIRedactFilter)

  • A custom logging.Filter subclass redacts emails, URLs, and IPv4 addresses (excluding 127.0.0.1)
  • Attached to both the file handler (.remote_mouse_logs/events.log) and stdout handler
  • Redacted text replaced with <email>, <url>, <ip>

8. Static File Whitelist (ALLOWED_STATIC_EXTS)

  • Only .js, .css, .png, .ico, .svg, .json, .map extensions are served
  • All other static file requests return 404
